# Skills 后台化队列 + 步骤动画优化

## 上下文
- 前端 nano2 页面 AI 生图功能，当前有三套独立调用体系需统一
- 后端 Skills API 使用 BackgroundTasks + 内存字典，无持久化无队列
- 已有 Redis Pub/Sub + WebSocket 实时推送基础设施
- 已有 WuyinkejiProvider 封装速创 API
- 队列技术选型：Redis List + asyncio（复用现有 Redis，零新依赖）

## 计划

### Phase 1: 后端 - Redis 任务队列核心

#### Step 1.1: 创建任务队列服务 `backend/app/services/task_queue.py`
- `TaskQueue` 类：Redis List 操作封装
  - `enqueue(queue_name, task_data)` → LPUSH
  - `dequeue(queue_name, timeout)` → BRPOP
  - `get_queue_length(queue_name)` → LLEN
- 任务数据结构：`{task_id, skill_id, template_id, form_data, size, quality, created_at}`
- 队列名：`skills:queue:{skill_id}`

#### Step 1.2: 创建 Skills Worker `backend/app/services/skills_worker.py`
- `SkillsWorker` 类（asyncio 后台服务）
  - `start()` → 启动消费循环
  - `stop()` → 优雅关闭
  - `_process_task()` → 步骤化执行：
    1. `validating` → 参数校验，发布进度 5%
    2. `prompt_building` → 提示词构建，发布进度 15%
    3. `api_submitting` → 提交速创API，发布进度 30%
    4. `generating` → 轮询结果，发布进度 50-90%
    5. `completed` / `failed` → 发布最终结果
  - 每步通过 `TaskPublisher.publish_status()` 发布
  - 使用 `WuyinkejiProvider` 调用速创 API
  - 任务完成后更新 PostgreSQL `ImageTask` 表

#### Step 1.3: 重构 Skills API `backend/app/api/v2/skills.py`
- `POST /generate` 改为入队操作：
  - 验证参数 → 构建任务数据 → LPUSH → 返回 task_id
  - 不再使用 BackgroundTasks
- `GET /tasks/{task_id}` 改为查询 PostgreSQL：
  - 直接查 ImageTask 表
  - 兼容 WebSocket 推送
- 新增 `GET /queue/status` 查看队列状态
- 新增 `POST /tasks/{task_id}/cancel` 取消排队中的任务

#### Step 1.4: 更新 `backend/app/main.py`
- lifespan 中启动/停止 Worker
- 新增配置项：`SKILLS_WORKER_CONCURRENCY`（默认1）

### Phase 2: 后端 - CLI 入口

#### Step 2.1: 创建 CLI 模块 `backend/app/cli/__init__.py`

#### Step 2.2: 创建 CLI 命令 `backend/app/cli/skills.py`
- `python -m app.cli.skills generate --template <id> --prompt <text> --size <size>`
- `python -m app.cli.skills list-templates [--skill <id>]`
- `python -m app.cli.skills task-status <task_id>`
- CLI 模式直接调用 Worker 逻辑，不入队（同步执行）
- 输出结构化 JSON，支持 `--json` 标志
- 支持 `--watch` 实时显示步骤进度

#### Step 2.3: 创建 `backend/app/cli/__main__.py`
- 支持 `python -m app.cli` 入口

### Phase 3: 前端 - 统一适配器

#### Step 3.1: 创建统一适配器 `src/lib/api/adapters/SkillQueueAdapter.ts`
- 实现 `ImageGeneratorAdapter` 接口
- `generateImage()`:
  1. POST `/api/v2/skills/generate` 提交任务
  2. 建立 WebSocket 连接 接收步骤状态
  3. 解析步骤消息 → 转换为 `onProgress` 回调
  4. 完成时返回图片 URL 数组
- 步骤映射：
  ```ts
  validating      → 5%
  prompt_building → 15%
  api_submitting  → 30%
  generating      → 50-90%（线性插值）
  completed       → 100%
  ```
- 支持 AbortController 取消
- 兼容轮询降级（WebSocket 连接失败时）

#### Step 3.2: 更新适配器注册 `src/lib/api/adapters/index.ts`
- `gpt-image-2` → `SkillQueueAdapter`
- 保留旧适配器作为 fallback

### Phase 4: 前端 - 步骤动画组件

#### Step 4.1: 创建步骤动画组件 `src/components/TaskStepAnimation.tsx`
- Props: `steps: TaskStep[]`, `currentStep: string`, `progress: number`
- 渲染步骤列表，当前步骤高亮 + 脉冲动画
- 已完成步骤显示 ✓ 图标
- 未执行步骤灰色
- 底部进度条
- 支持深色/浅色主题

#### Step 4.2: 更新 SkillsTaskNode `src/components/nanoai-workflow/nodes/SkillsTaskNode.tsx`
- 替换轮询逻辑 → 使用 SkillQueueAdapter
- 替换 "正在生成图片..." → 嵌入 TaskStepAnimation
- 传递 WebSocket 步骤信息

#### Step 4.3: 更新 GenerationPanel `src/components/GenerationPanel.tsx`
- 进度条区域替换 → 步骤动画（当使用 gpt-image-2 时）
- 保留其他模型的进度条样式不变
- 步骤信息通过 onProgress 回调传递

### Phase 5: 清理与测试

#### Step 5.1: 清理冗余代码
- `backend/app/services/skills/gpt_image_2/generate.py` 中的 `ImageGenerator` 内存任务管理 → Worker 替代
- 前端 `suchuang-api.ts` 中硬编码 API Key → 确认所有路径走后端

#### Step 5.2: 验证
- 手动测试 nano2 页面文生图完整流程
- 验证 WebSocket 步骤推送
- 验证 CLI 命令
- 验证队列并发和任务持久化
