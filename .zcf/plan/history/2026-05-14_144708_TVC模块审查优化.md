## 阶段 A：后端重构（优先）

### A1. 拆分 workflow_tasks.py → 4 文件

**当前**: workflow_tasks.py (999 行，路由+引擎+6个Provider闭包+3个轮询函数)

**拆分后**:
- `workflow_tasks.py` — 路由层（submit/get/cancel/progress SSE），~240 行
- `tvc_engine.py` — 执行引擎（_execute_tvc 5步编排 + 积分扣减 + 失败退款），~120 行
- `tvc_providers.py` — 6 个 Provider 闭包（_gen_one_jimeng/_gen_one_gpt_image_2/_gen_one_minimax/_submit_video_seedance/_submit_video_minimax/_submit_video_glm），~300 行
- `tvc_polling.py` — 3 个轮询函数（_poll_glm_video/_poll_seedance/_poll_minimax_video），~120 行

**原子操作**:
1. 创建 `backend/app/api/v2/tvc_providers.py`，迁移 `_gen_one_jimeng`、`_gen_one_gpt_image_2`、`_gen_one_minimax`、`_submit_video_seedance`、`_submit_video_minimax`、`_submit_video_glm`，统一导出 `get_image_provider(image_model, settings)` 和 `get_video_provider(video_model, settings)` 工厂函数
2. 创建 `backend/app/api/v2/tvc_polling.py`，迁移 `_poll_glm_video`、`_poll_seedance`、`_poll_minimax_video`
3. 创建 `backend/app/api/v2/tvc_engine.py`，迁移 `_execute_tvc`、`_call_glm_tvc_script`、`_optimize_prompts`、`_breakdown_shots`、`_generate_images`、`_generate_videos`、`_generate_bgm`
4. 精简 `workflow_tasks.py` 仅保留路由层 + SubmitRequest/NodeDef schema
5. 更新 `tvc_engine.py` import 指向新文件

### A2. 修复积分扣减逻辑（问题 6）

**文件**: `tvc_engine.py`
- `_execute_tvc` 开始时预扣积分（调用 points_service）
- 成功完成：不操作（已扣）
- 失败/取消：退还已扣积分
- 新增 `_deduct_points(task_id, user_id, req)` 和 `_refund_points(task_id, user_id)` 函数

### A3. 修复静默失败（问题 7）

**文件**: `tvc_engine.py`
- `_optimize_prompts` 返回空 shots 时抛异常而非静默返回
- `_breakdown_shots` 补齐镜头时记录 warning 日志

### A4. 修复批量并行（问题 9）

**文件**: `tvc_engine.py` 的 `_generate_images`
- 将串行 for 改为 `asyncio.gather` 真正并行每批 3 张
- 保持 subtask 状态更新顺序

### A5. 修复 Redis 竞态（问题 10）

**文件**: `backend/app/services/workflow_executor.py`
- `update_node` / `update_subtask` 使用 Redis WATCH/MULTI 乐观锁
- 或使用 `redis_client.set` 的 `get` + `cas` 模式（简化版：加载→修改→条件写回）
