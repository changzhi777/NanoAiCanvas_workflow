# API Key 管理和多任务并行优化方案

**任务**: 前后端 API 路由对齐 + API Key 热加载管理 + 多任务并行
**创建时间**: 2026-05-05
**状态**: 待用户批准

---

## 现状分析

### 路由现状

| 组件 | 路由 | 问题 |
|------|------|------|
| 前端 Adapter | `/v2/image/nanobanana2/generate` | 直接调用，无 API Key 绑定 |
| nginx | `/nano2/api/` → `/api/` | 已修复 |
| 后端 | 只有 `/api/` 前缀路由 | 缺少 `/v2/image/` 路由 |

**根本问题**: 后端没有 `/v2/image/nanobanana2` 等路由文件，这些在远程服务器。

### API Key 现状

- 后端 `providers/` 硬编码 API Key
- 无用户 → API Key 绑定
- 无热加载机制

## 方案设计

### 架构设计

```
前端请求 (X-API-Key: FRONTEND_KEY_1)
    ↓
API Gateway (Backend)
    ↓
Key Mapper (根据 frontend_key 查找 backend_keys)
    ↓
模型路由 (根据 model 选择具体 backend_key)
    ↓
Provider 调用
```

### 核心数据结构

**表: api_key_configs** (热加载配置)
```sql
CREATE TABLE api_key_configs (
    id SERIAL PRIMARY KEY,
    frontend_key VARCHAR(64) NOT NULL UNIQUE,
    description TEXT,
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- 每个 frontend_key 对应多个 backend_key
CREATE TABLE backend_key_mappings (
    id SERIAL PRIMARY KEY,
    frontend_key_id INTEGER REFERENCES api_key_configs(id),
    backend_key VARCHAR(128) NOT NULL,
    provider_type VARCHAR(32),  -- wuyinkeji, minimax, glm, etc.
    model_type VARCHAR(64),      -- nano-banana2, gpt-image-2, etc.
    mcp_config JSONB,            -- MCP 服务器配置
    skills JSONB,                -- 技能配置
    priority INTEGER DEFAULT 0,  -- 优先级
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_frontend_key ON api_key_configs(frontend_key);
CREATE INDEX idx_backend_key ON backend_key_mappings(backend_key);
CREATE INDEX idx_model_type ON backend_key_mappings(model_type);
```

**缓存策略**:
- 内存缓存 + 60 秒 TTL
- 后台每 30 秒刷新一次配置
- 调用时检查过期时间

### 步骤 1: 后端 - 创建 API Key 配置模块

**文件**: `backend/app/services/api_key_manager.py`
```
职责:
- 管理 frontend_key → backend_keys 映射
- 提供 model 到 backend_key 的选择逻辑
- 热加载配置（后台线程定期刷新）
```

**文件**: `backend/app/models/api_key.py` (新建)
```python
class ApiKeyConfig(Base):
    __tablename__ = "api_key_configs"
    frontend_key = Column(String(64), unique=True, nullable=False)
    description = Column(Text)
    is_active = Column(Boolean, default=True)
    backend_keys = relationship("BackendKeyMapping", back_populates="config")

class BackendKeyMapping(Base):
    __tablename__ = "backend_key_mappings"
    frontend_key_id = Column(Integer, ForeignKey("api_key_configs.id"))
    backend_key = Column(String(128), nullable=False)
    provider_type = Column(String(32))
    model_type = Column(String(64), index=True)
    mcp_config = Column(JSONB)
    skills = Column(JSONB)
    priority = Column(Integer, default=0)
    is_active = Column(Boolean, default=True)
    config = relationship("ApiKeyConfig", back_populates="backend_keys")
```

### 步骤 4: 后端 - API Key 中间件

**文件**: `backend/app/middleware/api_key_auth.py`
```python
@router.middleware()
async def api_key_auth_middleware(request: Request, call_next):
    if request.url.path.startswith("/v2/image/"):
        frontend_key = request.headers.get("X-API-Key")
        if not frontend_key:
            return JSONResponse({"error": "Missing API key"}, status_code=401)
        # 验证 key 是否有效
        manager = ApiKeyManager.get_instance()
        if not await manager.validate_key(frontend_key):
            return JSONResponse({"error": "Invalid API key"}, status_code=401)
    response = await call_next(request)
    return response
```

## 多任务并行设计

### 任务队列架构

```
前端请求
    ↓
POST /v2/image/generate
    ↓
Backend 提交到 Redis 队列
    ↓
立即返回 task_id
    ↓
Worker 进程从队列消费
    ↓
调用 wuyinkeji.com API
    ↓
更新任务状态到 Redis
```

**表: image_tasks** (任务状态)
```sql
CREATE TABLE image_tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id VARCHAR(64) UNIQUE NOT NULL,
    user_id UUID REFERENCES users(id),
    frontend_key VARCHAR(64),
    model_type VARCHAR(64),
    status VARCHAR(32),  -- pending, processing, success, failed
    request_params JSONB,
    result JSONB,
    error TEXT,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_task_id ON image_tasks(task_id);
CREATE INDEX idx_user_status ON image_tasks(user_id, status);
```

### 并行执行控制

- Redis 队列 + 多个 Worker
- 每个用户最多 3 个并发任务
- 全局最多 10 个并发调用外部 API

## 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 缓存导致配置延迟 | 配置更新不能立即生效 | 缩短 TTL 到 30 秒，提供手动刷新接口 |
| 外部 API 限流 | 并发高时失败 | 实现重试机制和任务队列 |
| 数据库连接池耗尽 | 高并发时响应慢 | 优化连接池配置 |
