## 维度一：算法谱系（四大流派）

| 流派 | 代表算法 | 原理 | 鲁棒性 | 速度 |
|---|---|---|---|---|
| **空域** | LSB | 直接改像素低位 | 极弱（一压缩就没） | 极快 |
| **频域** | DCT / DWT / **DWT-DCT-SVD** | 频域系数微扰，人眼无感 | 中（抗缩放/轻压缩） | 快 |
| **深度学习 post-hoc** | HiDDeN (2018)、StegaStamp (2020 抗屏摄)、RivaGAN、TrustMark (Adobe)、**WAM** (Meta 2024) | 编码器-噪声层-解码器端到端训练 | 强（可定制抗性） | 中（GPU） |
| **扩散原生** | **Tree-Ring**（初始噪声指纹）、**Stable Signature**（微调解码器）、ZoDiac | 把水印种进生成过程本身 | 强（但可被平均攻击/覆盖） | 生成时零开销 |

关键认知：
- **水印 ≠ 加密**。水印是鲁棒嵌入（可提取、难去除），加密是可逆保护（密钥控）。加密后的文件没有"内容"，水印后的文件内容照常可用。**C2PA 数字签名是第三条路**（元数据+签名溯源，不侵入像素）。
- 频域方法（DWT-DCT-SVD）是 SD 生态默认，实现约 200 行 Python（cv2+pywt+numpy），**我们可直接复用/改造**。

## 维度三：检测工具生态

| 工具 | 检测对象 | 形态 | 备注 |
|---|---|---|---|
| **invisible-watermark CLI** `python -m invisible_watermark decode` | dwtDct/Svd 水印 | 本地 Python | SD 图像第一检测入口；A1111/ComfyUI 出图直接可验 |
| **SynthID Detector** | SynthID 全家 | Web 门户（登录制） | 2026-10 开放公网；可测图/视频/音频 |
| **WAM detector** | WAM/Content Seal | 本地 Python（GPU） | 位级+局部化，还能定位被篡改区域 |
| **C2PA verify**（verify.contentauthenticity.org / c2paviewer.com） | C2PA 凭证 | Web / Rust SDK | 验"谁签的、改过没有"；OpenAI Verify 也汇入此体系 |
| 视频帧抽样 + 图像检测器组合 | 任意视频 | 自建管线 | **H3 场景的务实检测路径**（无通用视频盲检开源品） |
| **gcmark.com**（人工智能生成合成内容标识服务平台） | 按 TC260 标准的标识内容 | Web 平台 | 网安标委官方；亦是合规标识/检测的国家队入口 |

检测原理两派：**informed**（知道水印内容，做相关性检验，如 SynthID 的假设检验 p 值）vs **blind**（盲提取解码，如 WAM/TrustMark）。informed 更准但需持有密钥——**商业闭环选 informed，公开核验选 blind**。

## 维度四：视频水印（H3 场景专项）

H3 输出 = H.264 编码 mp4，1080p/30fps 级。挑战与对策：

1. **压缩即头号敌人**：H.264 量化破坏频域微扰 → 纯 DCT 类图水印嵌视频存活率低。Video Seal 训练时就把 codec 失真放中间层，鲁棒性最高。
2. **时序一致性**：逐帧独立嵌会被帧间压缩"平均掉"，或被抽帧丢弃。Video Seal 的 **temporal propagation**：关键帧嵌入+时序传播，效率高一个量级。
3. **务实分级路线**（开发映射）：
   - L1 快速版：关键帧 dwtDct 嵌 64-bit ID + ECC，ffmpeg 管线集成（H.264 CRF≤23 下可存活，缩放/转码存活中等）
   - L2 强化版：Video Seal 模型本地推理（GPU 需求中等，MIT 许可），抗转码+几何
   - L3 合规版：C2PA manifest 签名进 mp4 元数据（c2patool），与像素水印双保险
4. **注意**：H3 视频下游若走微信/抖音二次压缩（通常 CRF 很狠），L1 存活性会下降——L2/L3 是刚需方向。

## 维度五：SD 2.0 专项

- SD 2.0/2.1 官方与 A1111 WebUI 出图**默认嵌 invisible-watermark**（payload `StableDiffusionV1`）；ComfyUI 默认**不嵌**——我们管线里的 NB21/SD 出图属后者，需主动嵌。
- 嵌入接口极简：`WatermarkEncoder().encode(bgr, 'dwtDct')`（先 `set_watermark('bytes', wm)`）；解码 `WatermarkDecoder('bytes', 64).decode(bgr, 'dwtDct')`；CLI：`invisible-watermark -a encode/decode -m dwtDct -w/-l`。
- 鲁棒边界（决定可用性）：**过微信/抖音这类会缩放转码的通道后大概率解不出**——水印 ID 要留在**不经转码的分发链**里，或配合元数据/C2PA 双轨。
- SD 侧若要**生成时内嵌**（不做事后处理）：Stable Signature 路线（微调解码器），仅适合自部署权重；API 制出图只能 post-hoc。
- 已知短板：dwtDct 对 **diffusion 再生成攻击脆弱**（见维度六），高价值内容建议升 WAM 或频域+元数据双轨。

## 维度六：攻击面与鲁棒性基准

| 攻击 | 原理 | 对抗谁 |
|---|---|---|
| **再生攻击**（Zhao et al., NeurIPS 2024, [watermarkattacker](https://github.com/xuandongzhao/watermarkattacker)） | 加噪毁水印 → 扩散重建图像，"可证明移除" | StegaStamp/HiDDeN/dwtDct 几乎全灭 |
| 平均攻击 | 多张同模型图平均消除内容无关指纹 | Tree-Ring 类内容无关水印 |
| 覆盖攻击（ZoDiac） | 用更强水印覆写 | Stable Signature/Tree-Ring |
| 日常失真 | 截屏/缩放/裁剪/重压缩/微信转发 | 全部（程度不同） |

防御共识：**多域嵌入（频域+元数据）、ECC、密钥化（informed 检测）、双侧冗余**。没有打不破的像素水印，目标是"提高作恶成本 + 合规留痕"。

## 维度九：检测器生态（"这内容是 AI 生成的吗"）

三道防线，按可靠性递减：

### 9.1 水印/凭证检测（最可靠——需要内容方配合）
- 见维度三。我们**自己嵌的 ID 自己能验**（informed），这是商业闭环最硬的证据链。
- 水印在 → 出处铁证；水印被攻击掉 → 落入 9.2/9.3。

### 9.2 AIGC 统计检测器（无需水印，概率判断）
| 工具/方法 | 类型 | 备注 |
|---|---|---|
| CNNDetection / UniversalFakeDetect | 学术开源 | 频域伪影+泛化路线，对未见生成器泛化是核心难题（AIGIBench 基准） |
| [Awesome-AIGCDetection](https://github.com/) 清单 | 学术汇总 | GenDet、变分信息法等开源实现 |
| Hive Moderation / Sightengine | 商业 API | 工业级 AIGC+深伪检测，按量计费 |
| lynote-ai/ai-image-detector | 开源 CLI | 概率输出+报告，轻量 |
- **共识**：检测器是猫鼠游戏，对新模型（NB21/新 H3）泛化会退化；**只能做辅助证据，不能做法律证据**。

### 9.3 深伪视频检测（时序维）
- 学术 SOTA 走向**时空不一致性动态建模**（STIL → RTIL → SIFA-Net 2026），对时序对抗攻击仍脆弱（2026-05 arXiv）。
- H3 生成视频若需自证，**水印+凭证链远优于检测器路线**。

### 9.4 检测管线设计要点（映射开发）
```
输入文件 → ①元数据层：C2PA 验证 + EXIF/XMP 隐式标识字段
        → ②水印层：dwtDctSvd 解码（多原点搜索）→ 命中我们的 ID = 铁证
        → ③统计层：AIGC 检测器概率（辅助）
        → 汇总报告（证据分级：铁证/强证据/概率）
```

## 维度十：监测体系（"我的内容被谁搬了"）

### 10.1 指纹库（监测的地基）
**pHash 感知哈希**——本机实测（imagehash，2752×1536 锚图）：

| 变换 | pHash 距离/64 | 判定（阈值 10） |
|---|---|---|
| JPG q85 / 缩放回采 / 亮度 / 对比度 / 隐形水印后 | **0** | 同图 ✅ |
| 旋转 3° | 8 | 同图（边缘） |
| 裁剪 10% | 12 | ❌ 误判异图（pHash 弱点） |
| 异图（王后肖像） | 28 | 异图 ✅ |

- 结论：**pHash 是监测指纹首选**（同图 0-8 / 异图 20+，间隔清晰）；裁剪需配**分块 pHash / 多窗口**策略兜底。
- 视频指纹 = 关键帧 pHash 库（+ 时序）；**音频指纹**（解说音轨是强指纹）：开源 Dejavu / Audfprint（抗噪）/ Chromaprint（近重复）——搬运视频改画面也逃不过音轨。

### 10.2 监测通道
| 通道 | 工具/服务 | 成本 |
|---|---|---|
| 反向图搜 | TinEye API $0.03-0.04/次（862 亿索引）；MatchEngine $200/mo 自建库 | 商业 API |
| 图像/视频近重复检测 | Sightengine $99/mo 40K ops | 商业 API |
| 平台内监测 | YouTube Content ID（参考文件+指纹库+全量上传扫描，权利人可 Block/Track/收益）；微信原创保护；抖音版权 | 平台准入制 |
| 自建爬取 | 关键词/账号监控 + 帧抽样 + pHash 比对 | 开发成本 |

### 10.3 监测管线设计要点（映射开发）
```
指纹库：每条成片/图 → pHash + 关键帧 + 音频指纹 + 水印 ID + C2PA UUID（五元组入库）
监测环：定时任务 → 渠道抓取(关键词/反向图搜 API) → 候选比对(pHash 阈值+音频指纹)
      → 命中 → 二次取证：水印解码提取 ID + C2PA 查验 → 告警 + 存证(时间戳)
```
- **五元组指纹 + 水印 ID 复核**是核心设计：pHash 命中给候选，水印解码给出"确系我们内容"的铁证，两层互补（pHash 怕裁剪、水印怕转码，交叉覆盖）。

## 维度十一：音频水印（TTS 音轨保护专项）

我们成片音轨 100% TTS 生成（英文播音员/胡总音色）——音频域是独立战线：

| 工具 | 出品 | 特性 | 备注 |
|---|---|---|---|
| [AudioSeal](https://github.com/facebookresearch/audioseal) | Meta, ICML 2024 | generator/detector 架构，**局部化检测**（哪一段被水印），SOTA 鲁棒，MIT 开源 | ⚠️ 2025 研究（UCC）：区分 AI 语音与真人语音的可靠性存疑 |
| [WavMark](https://www.alphaxiv.org/abs/2308.12770) | 学术开源 | **1 秒音频嵌 32-bit**，抗噪强 | 容量小但稳 |
| SynthID Audio | Google | 闭源 | 已进 Detector 门户 |

- **场景映射**：TTS 音轨出片时嵌 AudioSeal/WavMark → 被搬运后**抽音轨即可验源**（画面被换掉也逃不掉，与视觉指纹互补）。
- 关键帧水印（视觉）+ 音轨水印（听觉）双域嵌入 = 搬运者必须同时重绘画面+重新配音才能洗掉——**作恶成本逼近重做**。

## 维度十二：国内平台 AIGC 标识实践（分发渠道硬约束）

- **《标识办法》第十条**：用户发布生成合成内容**必须主动声明**并使用平台标识功能；任何组织/个人不得恶意删除、篡改标识。
- **抖音**（跑在最前）：① AI 内容提示标识功能 ② **AI 元数据标识读写功能** ③ AIGC 识别专项模型（文字特征+**频域分布**特征识别，对流行 AIGC 模板定向判断）。
- **微信视频号**：发布时可勾选"内容由 AI 生成"声明。
- 微信/抖音/B站/微博/小红书均已改用户协议：不主动标识 → 平台处置（限流/下架）。
- 现实缺口（中青报调查）：隐去水印仍能发布的漏网案例存在，平台在补主动识别能力。
- **对我们的影响**：
  1. 发布 AI 内容必须平台内主动声明（合规动作，写进发布 SOP）
  2. 抖音会读**元数据隐式标识**并按频域特征反推 AIGC——我们的内容即使不打标也会被平台识别为 AI，主动标识是唯一正路
  3. 自嵌水印与平台识别**不冲突**（双轨并行，还强化我们的溯源能力）

## 维度十三：取证与司法效力（监测命中后的闭环）

- **司法依据**：最高法 2018《互联网法院审理案件规定》第 11 条——**电子签名、可信时间戳、哈希值校验、区块链**固定的电子数据可作为认定事实依据；2022《加强区块链司法应用的意见》32 条；全国 3500+ 法院司法区块链平台在线核验。
- **取证实务**：
  - 可信时间戳（TSA 联合信任时间戳服务中心）广泛用于图片版权取证，北互认可其完整性固化作用
  - 取证程序合法性决定采信：平台需记录网络环境/设备状态，**电子数据来源不可靠则不被采信**
  - 版权存证链：创作即存证（发布前指纹+哈希上链/时间戳）→ 侵权命中 → 页面/视频录屏取证（含 URL/时间/身份）→ 出证报告
- **对监测管线的映射**：命中告警自动触发**取证包生成**（命中截图 + 指纹比对报告 + 水印解码报告 + 时间戳/链上存证）——设计阶段的取证模块需求已明确。

| 攻击演化 | 再生攻击（NeurIPS 2024）→ 黑盒伪造（CVPR 2025）→ SemanticRegen 三段式部分再生（2025）→ **LLM 引导攻击**（ACM 2026） | 语义水印也被破 |

| 前沿汇总 | GitHub survey《Secure Watermarking and Traceability in Diffusion Models》 | 持续追踪入口 |

### 自研方案设计要素（设计阶段直接引用）
1. **ID 编码**：项目前缀 + 时间戳 + 内容序号 + 校验（128/256-bit，容量推导见缺口⑤）
2. **ECC 选型**：BCH 可精确指定纠错符号数；⚠️ 高误码率信道（低质 JPEG/狠转码）下 BCH 失效——**纠错能力与冗余度的平衡要按目标信道实测标定**（我们的实测矩阵已给基础数据）
3. **密钥体系**：informed 检测（持密验伪）做商业闭环；blind（公开可验）做第三方核验——**双层密钥设计**（私有主密钥 + 公开指纹）
4. **算法选择**：图像 dwtDctSvd（本机已验证）→ 视频关键帧 + 时序 → 音轨 AudioSeal/WavMark → 元数据 C2PA 全程签名
5. **嵌入位置纪律**：色度通道（不可见）+ 多通道冗余；避开 argmax 类不稳定定位（dwtDct 教训）

## 维度十八：实战攻击矩阵 + WAM 本机实装（2026-10-18 实测）

### 18.1 invisible-watermark（RS 40dB 版）真实威胁表现 —— 能力边界标定

对已交付的水印图（1792×2400 人像）打真实分发攻击：

| 攻击 | 位误码 | RS(20,8) 纠 6B | 判定 |
|---|---|---|---|
| JPG q85 / H.264 crf23 / 缩放+回采 | 0 | ✅ | **适用域** |
| **JPG q60（微信级压缩）** | 18（11%） | ❌ 需纠 ~15B | **边界外** |
| **截屏 72%+q70** | 54（34%） | ❌ | **边界外** |
| **裁剪 15% 回采** | 72（45%） | ❌ | **边界外** |

**结论：频域微扰方案的物理极限**。堆 RS 冗余无效（冗余↑→块密度↓→误码↑，恶性循环）。q60/截屏/裁剪正是真实分发最常见的失真——**P2 的 WAM 实装从"可选"升级为"必要"**。

### 18.2 WAM 本机实装 ✅（MPS 全跑通）

- 环境：torch 2.13 + MPS ✓；repo `facebookresearch/watermark-anything`；权重 `wam_mit.pth` 378MB（MIT 许可，dl.fbaipublicfiles 直链）
- 嵌入/检测：秒级（1792×2400 图）；32-bit message
- 实装坑：①imgs_w 在 **normalize 域**，须 `unnormalize_img` 回像素再存图（否则存出坏图）②mask logits 需 sigmoid ③MPS 不支持 float64，masked 投票须挪 CPU

### 18.3 WAM vs invisible-watermark 同图同攻击对比（queen3 实测）

| 攻击 | invisible-watermark+RS | **WAM** |
|---|---|---|
| 无攻击 | ✅ | ✅ mask 1.00 / bit 100% |
| JPG q60 | ❌ | ✅ **100%** |
| JPG q30 | ❌（39% 误码） | ✅ **100%** |
| 缩放 30% 回采 | ✅ | ✅ 100% |
| 截屏 72%+q70 | ❌ | ✅ **100%** |
| 裁剪 15% 回采 | ❌（45% 误码） | ✅ **100%**（mask 局部化 0.86，正确圈出水印区） |

**WAM 四个场景全胜**——invisible-watermark 的全部失败场景被覆盖，且裁剪时能**定位水印区域**（篡改取证能力）。局部化特性还支持"拼接图分区验真"。

### 18.4 路线决策（设计阶段输入）

- **双层水印定案**：L1 = invisible-watermark+RS（轻量全 CPU，抗轻度失真链）+ L2 = **WAM 引擎**（MPS/GPU，抗重度失真）——双引擎按内容价值分级启用
- 检测端：wm_detect 加 WAM 提取器（多消息/局部化），与 RS 解码并行投票
- WAM 集成注意：像素域/normalize 域转换、sigmoid mask、CPU 投票（三坑已排）

### 19.1 实装记录
- 环境：repo `facebookresearch/videoseal` + 权重 `y_256b_img.pth`（228MB，v1.0 稳定版 256-bit）；MPS **段错误**（算子兼容）→ **CPU 全链跑通**

### 19.3 对比结论（视频侧路线定案）

| | 关键帧 invisible-watermark | **Video Seal v1.0** |
|---|---|---|
| 容量 | 56-bit（测试）/128-bit（可扩） | **256-bit** |

- VideoSeal 本机深调结论：嵌入行为对帧数/消息图案敏感（60 帧与 362 帧、随机与固定消息表现不一致，未文档化）→ **标记实验性，不入主路径**

- 视频侧定案：**deep = 全帧频域（crf≤23 保证，任意帧可验）**；crf28+ 重压域像素水印物理失效，靠 C2PA 凭证 + pHash 指纹兜底；VideoSeal/WAM 视频版待官方成熟再入 L2

## 附：本机实测记录（2026-10-18，Python 3.14 / numpy 2.x / opencv / M 系列）

### invisible-watermark 源码真相
- **`'dwtDct'` 实际走 `EmbedMaxDct`**（非 dwtDctSvd！命名误导）：YUV-U 通道 → 一级 Haar DWT 低频带 → 4×4 分块 → 取**绝对值最大非 DC 系数**量化编码（scale=36，量化中心 9/27）→ 位循环散布 + 多数量子投票解码
- **`'dwtDctSvd'`**：同框架，但把 bit 编进 DCT→SVD 的**最大奇异值 s[0]**（恒为最大，无定位歧义），单通道

### 重大发现：dwtDct 在大图上解码不可靠（库的固有缺陷）
- 实测 2752×1536 图（锚图）：dwtDct 直接解码误码 **58-62%**（近随机）——**argmax 量化写入后幅值排序翻转，解码端定位漂移**
- 单帧最小复现 8/8 对齐 → 排除环境，锁死算法缺陷
- **dwtDctSvd 同图 0 误码**（直接解 + JPG q85 均 ✅，PSNR 41.4dB）→ **自研工具定 dwtDctSvd 路线**（或 maxDct 加"写入后 argmax 不变性校验"修复）
- 此发现解释了社区大量"SD 水印检不出"的报告

### dwtDctSvd 攻击矩阵（56-bit，2752×1536 锚图）

| 攻击 | 结果 |
|---|---|
| JPG q85 | ✅ 0 误码 |
| 高斯噪声 σ6 | ✅ 0 误码 |
| **H.264 crf23 转码帧** | ✅ **0 误码（H3 关键帧路线实证可行）** |
| 缩放 75% / 50%（直解） | ❌ 23/56（块网格错位） |
| **缩放 + 重采样回原尺寸** | ✅ **0 误码全恢复（检测管线标准操作）** |
| 裁剪 10% 中心 + 回采 | ❌（原点偏移非块宽整数倍 → 多原点平移搜索可解，自研点） |
| 亮度 +12 | 🟡 3/56（ECC 可纠） |
